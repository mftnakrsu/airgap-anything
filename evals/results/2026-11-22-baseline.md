## Notes

- A scan of each run's tool calls found no read outside its run directory, apart from run 7's throwaway copy of its own `.env.example` in `/tmp`, which its `docker compose config` check read; runs 4 and 8 also wrote such a copy there and deleted it unread. No tool call named this repository or the user's files.
- Harness context: the runs were subagents of a Claude Code session whose working directory was this repository, and each run's environment named that directory as its primary working directory. Each run also received the user's global instruction file, the user's memory index and the session's skill list, which includes the superpowers skills. Run 2 ran three web searches; no other run used the web.
- "Not seen" for F9 is no evidence, because this baseline cannot show F9. Its first clause, running two interviews, needs the skill: the risk is this skill and brainstorming each running one. Its second clause is suppressed by each scenario's "The user is not available for follow-up questions.", which leaves the agent no one to ask. The one-interview rule therefore stays in `SKILL.md`, as the risk table of the design spec requires, and the runs with the skill test it.
