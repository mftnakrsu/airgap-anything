## Facts

### Q1. `.claude-plugin/plugin.json`
The manifest file itself is optional; without it Claude Code loads components from the standard layout. When written it lives at `.claude-plugin/plugin.json`, and every other plugin file (`skills/`, `commands/`, `hooks/`) sits at the plugin root, not inside `.claude-plugin/`. The only required key is `name` (kebab-case; no spaces, `@`, `:` or path separators). Optional keys relevant to this repository: `version`, `description`, `author` (object: `name` required, `email` and `url` optional), `homepage`, `repository`, `license` (SPDX identifier such as `MIT`), `keywords` (array of strings), `displayName`, `icon`, `skills`, `engines`, `dependencies`. Setting `version` pins users to that version until it changes. `claude plugin validate` warns about a missing `version`, `description` or `author`. An unrecognized top-level key is stripped and reported as a warning. The plugin name must not start with `claude-` or `anthropic-` or pass as an Anthropic plugin; `airgap-anything` is clear of those rules. `claude plugin validate ./dir` is the authoritative check, and `--strict` turns warnings into failures. Source: https://code.claude.com/docs/en/plugins/manifest-reference.md (sections "Manifest file", "Fields", "`name`", "`version`", "Validate the manifest")

### Q2. `.claude-plugin/marketplace.json`
Required top-level fields: `name`, `owner` (object, `name` required, `email` and `url` optional) and `plugins` (array). `description` is optional but `claude plugin validate` warns when it is missing. The marketplace `name` uses letters, digits, `.`, `_`, `-`, starts with a letter or digit, contains no `..`, and must not be a reserved name (the list covers `claude-plugins-official`, `anthropic-*` and similar; `airgap-anything-marketplace` is not on it). Each plugin entry requires `name` and `source`; `description`, `version`, `category`, `tags` and `strict` are optional. For a repository that is itself the plugin, `source` is a relative path resolved from the marketplace root (the directory that contains `.claude-plugin/`); it must start with `./`, and `"."` on its own also means the root; the page's submodule section writes this case as `"source": "./"`. A path with `..` fails validation. The entry `name` is what users type before `@`; keep it equal to the `name` in `plugin.json`. When both the entry and `plugin.json` set `version`, `plugin.json` wins and validate warns, so set the version in one place. The reference plugin on disk uses `"source": "./"`. Tested: a scratch repository with `"source": "./"` passed `claude plugin validate .`. Source: https://code.claude.com/docs/en/plugins/marketplace-reference.md (sections "Top-level fields", "Plugin entries", "Plugin sources", "Relative path plugin source", "Reserved names"); https://code.claude.com/docs/en/plugin-marketplaces.md (section "Create a marketplace", step 2)

### Q3. Install commands
Add a GitHub-hosted marketplace: `/plugin marketplace add OWNER/REPO` inside a session, or `claude plugin marketplace add OWNER/REPO` in a shell. Append `#ref` to pin a branch or tag. Install: `/plugin install PLUGIN@MARKETPLACE` in a session, which opens the `/plugin` panel on that plugin's details so the user reviews it and picks a scope, or `claude plugin install PLUGIN@MARKETPLACE` in a shell, which installs directly. For this project that gives `/plugin marketplace add OWNER/airgap-anything` and `/plugin install airgap-anything@airgap-anything-marketplace`. The name after `@` is the top-level `name` of `marketplace.json` (the name the marketplace registered under), not the repository name; the name before `@` is the plugin entry's `name`. A one-step form exists: `/plugin install PLUGIN --marketplace OWNER/REPO` (session, Claude Code 2.1.275 or later) and `claude plugin install PLUGIN --marketplace OWNER/REPO` (shell, 2.1.292 or later). Installed plugin skills are invoked as `/PLUGIN:SKILL`, here `/airgap-anything:airgap-architect`; tested: `claude plugin validate` printed `airgap-anything:x` for a skill folder `x`. Source: https://code.claude.com/docs/en/plugins/install.md (sections "Add a marketplace", "Install from your shell", "Add a marketplace and install in one command"); https://code.claude.com/docs/en/plugins/host-marketplace.md (the table of hosting options and the sentence "Users install a plugin by its entry's `name` and the top-level `name` in your `marketplace.json`"); https://code.claude.com/docs/en/plugins/components.md (skills section, "Command name")

### Q4. Skills inside a plugin
Claude Code looks for `skills/<skill-name>/SKILL.md` under the plugin root, one directory per skill. The `skills` key in `plugin.json` adds more directories to scan on top of the default `skills/` scan; it does not replace it. With no `skills/` directory and no `skills` key, a `SKILL.md` at the plugin root loads as a single skill. The plugin skill's command is `/<plugin>:<directory>`; a `name` in the frontmatter replaces the last segment. A `CLAUDE.md` at the plugin root is not loaded as context, and `claude plugin validate` warns about it (tested: the warning reads "CLAUDE.md at the plugin root is not loaded as project context"; plain validate still exits 0, `--strict` exits 1). Source: https://code.claude.com/docs/en/plugins/manifest-reference.md (sections "Standard layout", "Fields" row `skills`); https://code.claude.com/docs/en/plugins/components.md (skills section); https://code.claude.com/docs/en/skills.md (section "Choose where skills load", the Plugin row)

### Q5. Agent Skills frontmatter
The Agent Skills specification requires `name` and `description`. `name`: 1 to 64 characters, lowercase letters (`a-z`), digits and hyphens only, must not start or end with a hyphen, must not contain consecutive hyphens, and must match the parent directory name. `description`: 1 to 1024 characters, non-empty, saying what the skill does and when to use it. Optional: `license`, `compatibility` (1 to 500 characters), `metadata` (string-to-string map), `allowed-tools` (space-separated string, experimental). The body should stay under 500 lines and the recommended instruction size is under 5000 tokens. Claude Code is looser: it treats every field as optional (`name` defaults to the directory name, `description` is recommended) and truncates the combined `description` and `when_to_use` text at 1,536 characters in its skill listing; it accepts many extra fields (`when_to_use`, `disable-model-invocation`, `user-invocable`, `paths`, `model` and others) that only Claude Code understands. For portability the SKILL.md therefore uses the specification's fields, and the 1024-character limit is the binding one. Source: https://agentskills.io/specification.md (served at https://agentskills.io/specification; sections "Frontmatter", "`name` field", "`description` field", "Progressive disclosure"); https://code.claude.com/docs/en/skills.md (section "Frontmatter reference" and "Using skill frontmatter outside Claude Code")

### Q6. `npx skills add`
The `skills` CLI (package `skills`, repository `vercel-labs/skills`) requires Node.js 22.20 or later. For a repository it searches: the root (if it holds a `SKILL.md`), `skills/`, `skills/.curated/`, `skills/.experimental/`, `skills/.system/`, and many per-agent directories (`.claude/skills/`, `.agents/skills/` and others). Containers are walked up to three levels deep, so `skills/airgap-architect/SKILL.md` is found. If `.claude-plugin/marketplace.json` or `.claude-plugin/plugin.json` exists, skills declared in those files are also discovered; this repository declares none, so only the `skills/` scan applies. Select one skill with `--skill airgap-architect` (short form `-s`), pick the agent with `-a claude-code`, list without installing with `--list`; the install is to the current project by default and `-g` installs for the user. Installation links to a canonical copy by default and `--copy` copies files instead. The docs do not state in one sentence that the whole folder is copied. The lock-file section does say the hash covers "every file in the skill folder" that the CLI installs into `.agents/skills/<name>`, and leaves out only `metadata.json` files and the `.git`, `__pycache__` and `__pypackages__` folders "because the installer does not copy them". So `scripts/`, `catalog/` and `references/` are installed with `SKILL.md`; a file named `metadata.json` anywhere inside the skill folder would not be, and nothing in the plan needs one. Source: https://github.com/vercel-labs/skills (README, read with `gh api repos/vercel-labs/skills/readme`); https://github.com/vercel-labs/skills/blob/main/docs/creating-skills.md (section "Skill Discovery", "Plugin Manifest Discovery"); https://github.com/vercel-labs/skills/blob/main/docs/commands.md (section "`skills add`", Options table, "Installation Methods")

### Q7. A skill's own files at run time
In Claude Code, `${CLAUDE_SKILL_DIR}` is the directory containing the skill's `SKILL.md`; for a plugin skill that is the skill's own subdirectory, not the plugin root. Claude Code substitutes it, and `${CLAUDE_PLUGIN_ROOT}` for plugin skills, in the skill's markdown content and in Bash rules of the `allowed-tools` frontmatter, so a skill can write `${CLAUDE_SKILL_DIR}/scripts/render.sh` and it resolves whatever the working directory is. The page says "the skill's markdown content" and the examples show `SKILL.md` only; it does not say whether files under `references/` that the agent reads later are substituted too (open question, see Deviations). `${CLAUDE_PLUGIN_ROOT}` is not present in the environment of commands that Claude runs through the Bash tool. For other agents the Agent Skills specification says to refer to other files with relative paths from the skill root (for example `references/REFERENCE.md` and `scripts/extract.py`) and to keep references one level deep from `SKILL.md`. Source: https://code.claude.com/docs/en/skills.md (section "Available string substitutions", the `${CLAUDE_SKILL_DIR}` row and the paragraph after the table; "Add supporting files"); https://code.claude.com/docs/en/plugins/manifest-reference.md (section "Environment variables"); https://agentskills.io/specification.md (section "File references")

### Q8. Anthropic's directory (added 2026-11-22)
A plugin is listed in Anthropic's directory by submitting its GitHub repository from the developer portal at claude.ai/directory/manage, which needs a paid claude.ai plan. The plugin folder is the folder that holds `.claude-plugin/plugin.json`; it can be a subfolder, and an install gets only that folder. The portal's **Validate** runs the directory's checks; a finding blocks, holds the version for a reviewer, warns or notes. For an organization that is not Verified, the portal refuses files other than Markdown, text, JSON, YAML and PNG, JPEG, GIF, WebP or ICO images, files that start with `#!`, SVG files other than the icon, package-manager files such as `package.json`, `.claude-plugin` folders other than the plugin's own, and fields outside an allowed list in `package.json`; it flags commands that download and run code, even in documentation, and holds files over 256 KiB that it cannot read and `.ico` images. Validated on 2026-11-22: with the repository root as the plugin folder, the portal blocked on `assets/brand/hero-dark.svg` and the `scripts` field of `docs-site/package.json`. With the plugin in `plugins/airgap-anything/` it blocked on `skills/airgap-architect/catalog/components/distribution-registry.toml`, the first file in the catalog, so the TOML catalog, and by the rule's wording the Python scripts, need Verified status. (A check of the `skills/` folder alone stopped at the missing `plugin.json` and did not reach the file types.) Verified means Anthropic knows the organization is a real company: a request, from **Help and appeals** > **Request verified**, needs a paid plan and a domain proven with a DNS TXT record, and a person checks that the legal name and website match the domain. Done on 2026-11-22: the portal gives a TXT record for the domain's own name, with a value that expires after a month if the domain is not proven; **Check** marks the domain as proven once the record resolves, and the record has to stay. The request form asks for a legal name, a website and an optional note, and sending it opens a case whose replies appear only on its page. The portal lists what Verified gives: permission to ship plugins that run code on the user's machine, the Verified badge, custom icons, and plugin names that use the organization's own brand. `claude plugin validate <dir> --profile directory` runs part of these checks locally, and a README at the repository root counts for a plugin in a subfolder. `claude plugin eval` reads eval suites only inside the plugin root (`--eval-dir` refuses `..`). Source: https://code.claude.com/docs/en/plugins/publish.md (section "Submit to Anthropic's directory"); https://claude.com/docs/plugins/submit.md; https://claude.com/docs/plugins/pre-submission-checklist.md; https://claude.com/docs/directory/publish.md (Verified status); the portal's validation reports; `claude plugin eval --help` (tested, Claude Code 2.1.330)
